# reviews/

**Post-implementation or independent reviews.**

> **Historical records — non-authoritative.** Reviews are point-in-time
> snapshots of what was verified on their date. They are evidence for the
> workflow, never current project state. For current state, read
> `docs/TASK.md` / `docs/PROJECT.md` / `docs/SYSTEM.md`.

Place reviews of completed implementations and independent reviews of audits here
(see `workflow/REVIEW.md` for the template).

## Naming

- `REVIEW-<shortname>.md` — review of a completed implementation
- `INDEPENDENT-REVIEW-<shortname>.md` — independent review of an audit/report

## Conventions

- Every review states the plan/audit it covers, its date, the reviewer role, and
  an overall verdict (APPROVED / APPROVED WITH NOTES / CHANGES REQUESTED).
- Reviews compare against the original plan, not an ideal redesign.
- Desktop AI verification is required for HIGH/CRITICAL changes; note it here.
